Kindle 本『冤魂志 第一集』を作る途中で、元になった飄燈閣の記事に誤りが見つかった。本ではもう直してある。それを web 記事にも当てる。

| `2_読んで直す.md` | 本の直しのうち、web 記事に同じ文がそのまま無いもの。web の該当箇所を読んで、同じ誤りがあれば直す | 26 |
| `3_10月に見つけた誤り.md` | 10月に本の手入れで見つけた誤りの一覧（言葉で書いてある） | 約50 |

## 1. 先に作る仕組み：記事の「版」と「訂正履歴」

閣主の決め（2026-10-27）：
- **中国語の誤り（漢字・簡体字・ピンイン・声調・語義の表）を直したら、版を上げる。** 読者が字を写して覚えるので、原文の字の訂正と同じ重さ。
- **日本語だけの直し（言い回し・言い過ぎを弱める・日本語の誤字）は、履歴に残すが版は上げない。**
- 訂正の一覧ページは今は作らない（記事ごとの記録で十分）。

作り方：
1. `src/content/config.ts` の blog の schema に、省略できる欄を足す：
   ```ts
   revisions: z.array(z.object({
     date: z.string(),          // 直した日（YYYY-MM-DD）
     note: z.string(),          // 何を直したか（日本語で一行）
     bump: z.boolean(),         // true＝版を上げる（中国語の直し）／false＝履歴のみ
   })).optional(),
   ```
2. 版の数＝`1 + （bump が true の件数）`。
3. 記事ページ（`src/pages/blog/[slug].astro`）で：
   - 題の下、日付の近くに、**版が 2 以上のときだけ**「第2版（2026-11-05 訂正）」と小さく出す（最後に版を上げた日）。
   - 本文の最後（「次の記事」などの前）に「訂正履歴」の小さな欄を出す。`revisions` を日付順に一行ずつ：「2026-11-05　ピンインの声調を直した（甚 shén→shèn ほか3か所）」。bump が true の行には「（第2版）」のように版を添える。`revisions` が無い記事には何も出さない。
   - 見た目は今のサイトに合わせる（小さく、控えめに）。

## 2. 訂正の当て方

### `1_機械で直せる.json`
- 各項目：`web`（記事のファイル名、`src/content/blog/` の中）・`前`・`後`・`種類`（「版を上げる」か「履歴のみ」）・`本`（本の原稿のどの話か、参考）。
- **上から順に**、`前` を `後` に置き換える。置き換える前に、`前` がその記事にちょうど一回あるかを確かめ、無い・二回以上なら置き換えずに報告する（あとから記事が変わっていた場合）。
- 記事ごとに、`種類` に「版を上げる」が一つでもあれば `bump: true`、すべて「履歴のみ」なら `bump: false` の revisions を一つ足す。`note` は直した中身を一行で（例：「ピンインの声調（甚・將吏ほか）と語義の言い過ぎを直した」）。

### `2_読んで直す.md` と `3_10月に見つけた誤り.md`
- web 記事の該当する箇所を読み、**同じ誤りが web にもあるときだけ**直す。無ければ直さず、報告に「web には無かった」と書く。
- `前`・`後` は本の文なので、web とは言い回しが違う。直すのは誤りの所だけ。本の文を丸ごと写さない。
- **本だけの言い方を持ち込まない**：「第IV章の張超の話」「章末付録」「この本」などは web にない。web では「冤魂志の『張超』の回」のように記事の言い方にする（リンクできるなら記事へのリンク）。
- 書き下し（「〜を〜す」のような訓読）の直しは、web の記事に書き下しが無ければ飛ばす。
- 判断に迷うものは直さず、報告に書く。
- 孔基（029・030）は、本では原文の底本を『法苑珠林』巻一一〇（四庫全書本）に差し替えた。今回は**出典の巻数（巻一一一→巻一一〇）だけ**直す。原文そのものの差し替えは別の機会にする。

## 3. 守ること
- main に直接 push しない。新しいブランチで PR にする。PR の説明は、プログラマーでない人にも分かる日本語で。
- 記事の `date` は変えない。
- このフォルダ（`docs/web訂正_2026-11-05/`）は残しておいてよい（サイトには出ない）。
- 終わったら `npm run build` が通ることを確かめる。直した記事を一つ選び、スマホ幅（390px）で「第2版」と「訂正履歴」の見え方のスクショを PR に載せる。
- 報告：記事ごとに「直した件数（版上げ／履歴のみ）・直さなかったものとその理由」を表にする。
